8. GitHub 프로젝트 활용 요약

저장소: github.com/you661012/holub-life (공개). 시작한 날(11/02)의 커밋 다섯 개를 빼면 모든 변경은 브랜치에서 작업하고 PR로 main에 합쳤다.

8-1. 운영 방식

  • GitHub Flow. 기능 하나마다 브랜치를 만들고(feature/…, fix/…, test/…, docs/…), PR을 올려 main에 합친 뒤 브랜치를 지웠다. PR 설명에는 무엇을, 왜, 어떻게, 확인한 것, 한계를 적었다.
  • main 보호. PR 없이 main에 직접 push할 수 없고 강제 push와 삭제를 막았다. .github/CODEOWNERS로 저장소 소유자의 승인을 요구하게 했다.
  • 커밋. 커밋 하나에 한 가지 일만 담았다. 원본 첫 커밋(648d9bd)을 그대로 두어, 원본과의 차이를 언제든 git diff로 볼 수 있다.
  • 결정과 근거를 함께 커밋. 설계 결정은 ADR(docs/decisions/)로, 결정의 근거가 된 측정은 실험 코드(docs/experiments/)로 코드와 같은 PR에 남겼다.
