8. GitHub 프로젝트 활용 요약

저장소: github.com/you661012/holub-life (공개). 시작한 날(11/02)을 빼면 모든 변경은 브랜치에서 작업하고 PR로 main에 합쳤다.

공식적으로는 6인 팀이지만 팀원과 연락이 닿지 않아 설계, 구현, 테스트, 문서를 모두 혼자 진행했다. 저장소의 커밋 작성자도 모두 한 명이다.

8-1. 운영 방식

  • GitHub Flow. 기능 하나마다 브랜치를 만들고(feature/…, fix/…, test/…, docs/…), PR을 올려 main에 합친 뒤 브랜치를 지웠다. PR #7부터는 설명을 무엇을, 왜, 확인한 것, 한계로 나눠 적었고 그 뒤에 "어떻게" 칸을 더했다.
  • main 보호. main에 합치려면 PR과 승인 1개가 필요하고, 그 승인은 .github/CODEOWNERS에 적힌 저장소 소유자의 것이어야 하게 했다. 강제 push와 삭제도 막았다. 팀원을 초대해도 소유자 승인 없이는 머지할 수 없게 하려던 것이다. 혼자 진행해서 승인해 줄 사람이 없었기 때문에 자기 PR은 관리자 권한(gh pr merge --admin)으로 머지했다. 관리자에게는 이 규칙이 강제되지 않는다.
  • 커밋. 커밋 하나에 한 가지 일만 담았다. 원본 첫 커밋(648d9bd)을 그대로 두어, 원본과의 차이를 언제든 git diff로 볼 수 있다.
  • 결정과 근거를 함께 커밋. 설계 결정은 ADR(docs/decisions/)로, 결정의 근거가 된 측정은 실험 코드(docs/experiments/)로 남겼다. 11/16에 결정 4-B, 4-C를 위해 잰 코드는 저장소 밖에서 돌려 남아 있지 않다.
