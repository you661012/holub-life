1. 프로젝트 요약

사용자가 Life Game의 규칙을 새로 정의해 적용할 수 있고 지금 판이 어떤 결말에 이를지 미리 알 수 있게 했다.

Allen Holub의 Life Game(v1.03, Java/Swing)을 바탕으로 기능을 두 가지 더했다. 원본이 하던 기능은 모두 그대로 동작한다. 두 기능은 한 줄기로 이어진다. 규칙을 입력하고 세포를 놓으면, 프로그램이 그 규칙으로 판을 미리 돌려 결말을 알려 준다.

확장할 수 있게 된 것설계의 중심
확장 1. 규칙 선택
E1 E2		 Rule 메뉴에서 Conway(B3/S23)와 HighLife(B36/S23)를 고르거나, B/S 표기(예: B36/S23)로 규칙을 직접 입력한다. 진행하는 도중에 바꿔도 다음 세대부터 새 규칙을 따른다. Strategy 패턴. Resident 안에 박혀 있던 Conway 식을 Rule 객체로 뺐다 (4장)
확장 2. 결말 예측
E3 E4		 창 아래에 세대 수, 살아 있는 세포 수, 현재 규칙과 함께 예측한 결말(소멸·정지·반복·미확정)과 남은 세대 수를 보여 준다. 예측한 소멸·정지에 도달하면 진행을 저절로 멈춘다. 화면의 판과 따로 좌표만으로 앞을 계산하는 모델(Generation)과, 두 스레드 사이의 잠금·작업자 설계 (5장)

이 프로젝트는 설계 개선과 기능 확장의 개수보다 설계 결정의 근거에 초점을 두었다. 4장(규칙 선택)과 5장(결말 예측과 자동 정지)에는 기능마다 원본과의 비교, 적용한 패턴, 검토한 다른 방법과 고른 이유를 적었다. 여러 결정은 두 방법을 작게 만들어 같은 판에서 돌려 본 결과를 보고 정했고 그 실험 코드는 저장소의 docs/experiments/에 남겨 두었다.

개발 환경과 결과

항목내용
언어와 빌드Java 21(Temurin), Gradle, JUnit 5. 실행은 ./gradlew run, 테스트는 ./gradlew test
원본저장소의 첫 커밋(648d9bd)이 수정 전 원본이다. 원본과의 차이는 git diff 648d9bd HEAD -- src/main으로 볼 수 있다
새로 만든 클래스확장 1: Rule, ConwayRule, HighLifeRule, BirthSurvivalRule, RuleHolder
확장 2: Generation, EndingPredictor, Ending, LiveCellCollector, PredictionRequest, PredictionWorker, StatusLine
고친 원본 클래스Resident(규칙 위임, transition() 반환값), Universe(메뉴, 예측 연결, 잠금, 자동 정지), Neighborhood(건너뛰기 조건 삭제), Life(상태 표시 한 줄)
고치지 않은 원본 클래스Cell, Clock, Publisher, Direction, MenuSite 등
테스트JUnit 테스트 113개, 모두 통과 (6장). 구조를 바꾸기 전에 쓴 원본 동작 테스트 9개가 바꾼 뒤에도 수정 없이 통과한다
기록설계 결정 기록(ADR) 5개 docs/decisions/ · GitHub 커밋 90개, PR 16개 (8장)
